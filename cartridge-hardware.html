Physical Cartridge Peripherals Overview: While standard GBA cartridges consist solely of mask ROM and optional battery-backed non-volatile save storage (SRAM, Flash, or EEPROM), a select group of commercial releases incorporate specialized physical hardware directly onto the cartridge printed circuit board (PCB). These include real-time clocks (RTC), optical photodiode solar sensors, dual-axis motion accelerometers, piezoelectric angular rate gyroscopes, and built-in or Joybus force-feedback vibration motors.

Cartridge Hardware Architecture & Register Specifications

Physical sensors and peripherals interface with the GBA CPU across two primary buses: memory-mapped cartridge GPIO registers (overlaying ROM space) and cartridge SRAM address space.

1. Cartridge GPIO Port Architecture (0x080000C4..0x080000C8)

Specialized cartridge PCBs implement a 4-bit general-purpose input/output (GPIO) controller mapped directly into the cartridge ROM bus header at addresses 0x080000C4..0x080000C8:

AddressRegister NameAccessBit Definitions & Description
0x080000C4 GPIO_PORT_DIRECTION R/W Bits 0..3: Pin direction mask. 1 = Output (GBA drives pin), 0 = Input (Cartridge peripheral drives pin). Bits 4..15: Unused.
0x080000C6 GPIO_PORT_DATA R/W Bits 0..3: Data line states. Writes output pin levels; reads sample incoming pin voltages from the cartridge peripheral.
0x080000C8 GPIO_PORT_CONTROL R/W Bit 0: Read/Write Enable. Writing 0x0001 enables write access to Direction and Data registers; writing 0x0000 locks the port and returns normal ROM data.

2. Real-Time Clock (RTC) Subsystem (65 Verified Titles)

Incorporates an external real-time clock integrated circuit (Seiko Instruments S-3511A or S-3530A 8-pin SOP) powered by an on-cartridge lithium coin battery to maintain continuous wall-clock time even when the Game Boy Advance is powered off.

Hardware IC
Seiko Instruments S-3511A / S-3530A / SIIRTC compatible 4-pin serial interface
Bus Wiring
Cartridge GPIO: Bit 0 = SIO (Serial Data bidirectional), Bit 1 = SCK (Serial Clock output), Bit 2 = CS (Chip Select output, active HIGH), Bit 3 = Unused
Communication Protocol
Synchronous 3-wire serial protocol. Commands: 0x06 (Reset), 0x60 (Status Register read), 0x64 (Read 7-byte Time Packet: Year, Month, Day, Day-of-Week, Hour, Minute, Second in BCD format)
SDK Signatures
SIIRTC_V001, SIIRTC_V, RTC_V
Key Verified Titles
Pokémon Ruby & Sapphire (AXV/AXP), Pokémon Emerald (BPE), Boktai 1/2/3 (U3I/A3I/U32/U33), Sennen Kazoku (BKA), Rockman EXE 4.5: Real Operation (BR4), Legendz series (BLJ/BLV), Pokémon 10th Anniversary Distribution (BUU), Aurora Ticket Distribution (JPA)
Clean-Room Note
Pokémon FireRed & LeafGreen (BPR/BPG) contain leftover SIIRTC_V001 string fragments from the Ruby/Sapphire codebase, but their cartridge PCBs lack RTC chips and rely solely on an in-game step counter.

3. Photodiode Solar Sensor Subsystem (9 Verified Titles)

Developed by Konami for Hideo Kojima's Boktai series. Features an optical photodiode sensor and analog-to-digital converter (ADC) mounted on the upper transparent cartridge edge to measure ambient sunlight and ultraviolet radiation.

Hardware Mechanism
Photodiode light sensor paired with serial comparator / ADC circuit on transparent cartridge PCB
Bus Wiring
Cartridge GPIO: Bit 3 = DOUT (Serial Data Out from ADC). Clock and latch lines bit-banged via GPIO bits 1 and 2.
Measurement Range
Bit-banged counter / ADC conversion measuring light intensity across 10 discrete solar bars (Level 0 = indoor / pitch dark, Level 10 = maximum direct sunlight)
In-Game Mechanics
Powers the protagonist's Solar Gun, charges battery stations, purifies immortal vampires in the Pile Driver, and grows Solar Trees
ROM Context Strings
"SOLAR SENSOR", "Solar Gun", "Solar"
Verified Titles
Boktai: The Sun Is in Your Hand (U3I, A3I), Boktai 2: Solar Boy Django (U32), Shin Bokura no Taiyou: Gyakushuu no Sabata (U33) (9 titles across USA, Europe, and Japan releases)

4. Tilt & Gyro Motion Sensors (6 Verified Titles)

Motion detection is implemented across two fundamentally distinct physical sensor architectures:

Architecture A: Memory-Mapped Tilt Accelerometer (ROHM BU3668K / ADXL202)

Used in Yoshi's Universal Gravitation / Yoshi Topsy-Turvy (KYG) and Koro Koro Puzzle Happy Panechu! (KHP). Mapped into the cartridge SRAM bus at addresses 0x0E008000..0x0E008500:

  • 0x0E008000: Write 0x55 (Latch conversion trigger phase 1)
  • 0x0E008100: Write 0xAA (Latch conversion trigger phase 2)
  • 0x0E008200: Read X-axis low byte (Bits 0..7)
  • 0x0E008300: Read X-axis high nibble (Bits 8..11) + Bit 7 Data Ready flag (1 = sample ready)
  • 0x0E008400: Read Y-axis low byte (Bits 0..7)
  • 0x0E008500: Read Y-axis high nibble (Bits 8..11)
Architecture B: Piezoelectric Gyroscope + AD7466 ADC (NEC/TOKIN Angular Rate Sensor)

Used in WarioWare: Twisted! / Mawaru - Made in Wario (RZW). Employs a ceramic piezoelectric vibrating gyroscope that detects angular rotational velocity rather than static gravitational tilt.

  • Sensor: NEC/TOKIN ceramic piezoelectric angular rate sensor detecting rotational speed (yaw).
  • Digitizer: Analog Devices AD7466 12-bit SPI ADC connected via Cartridge GPIO registers (0x080000C4..0x080000C8).
  • High-speed bit-banged SPI protocol reads 12-bit angular velocity samples, enabling high-precision rotational minigame controls.
  • Header Signatures: "WARIOTWISTED", "MAWARUWARIO".

5. Force-Feedback Rumble Motors (9 Verified Titles)

Haptic vibration feedback is delivered through two distinct physical mechanisms:

Cartridge Motor (Drill Dozer / Twisted)
Directly actuated via Cartridge GPIO Data register 0x080000C6 bit 3 (0x08), with Direction register 0x080000C4 bit 3 set to output. Writing 1 starts vibration; writing 0 stops. Drill Dozer (V49) features an enlarged cartridge casing with an internal AAA battery compartment to power the motor independently of the GBA console. WarioWare: Twisted! (RZW) includes an internal vibration motor providing tactile click feedback when rotating.
Game Boy Player Joybus Rumble
Actuated over the GBA Serial Link Port in Joybus mode via register 0x04000134 (RCNT = 0xC000). When played on Nintendo GameCube via the Game Boy Player peripheral, communicates with the GameCube hardware to vibrate the GameCube controller. Verified in Pokémon Pinball: Ruby & Sapphire (BPP, 4 regional titles).

Save Geometry Detection & Padding Stripping (SaveGeometry · gbakit save)

Clean-room tools in gbakit for identifying discrete cartridge non-volatile storage capacities and stripping flat emulator padding.

Physical Cartridge Memory vs. Emulator Container Padding: Standard GBA cartridges host discrete non-volatile memory chips:
  • EEPROM_512 (512 bytes / 4 kbit) — e.g. Super Mario Advance, Castlevania: Circle of the Moon
  • EEPROM_8K (8,192 bytes / 64 kbit) — e.g. The Legend of Zelda: The Minish Cap, Final Fantasy Tactics Advance
  • SRAM_32K (32,768 bytes / 256 kbit) — battery-backed static RAM, e.g. Metroid Fusion, Castlevania: Aria of Sorrow
  • FLASH_64K (65,536 bytes / 512 kbit / 64 KiB) — e.g. Pokémon Ruby & Sapphire, Super Mario Advance 4
  • FLASH_128K (131,072 bytes / 1 Mbit / 128 KiB) — e.g. Pokémon Emerald, Boktai: The Sun Is in Your Hand
Many emulators (including VisualBoyAdvance, older mGBA configurations, and hardware flashcarts) pad all save dumps to a flat 64 KiB (65,536 bytes) or 128 KiB (131,072 bytes) container using uniform 0x00 or 0xFF fill. gbakit save inspects this geometry, identifies candidate games without requiring a title code, and strips dead padding bytes with safety checks.

1. gbakit save probe <file.sav> [--json]

Loose save probing across all embedded gba-saves definitions. Evaluates slot magic signatures, active blocks, and checksum algorithms without requiring a game code. Outputs candidate matches, confidence scores, detected canonical geometry, and padding analysis.

# Loose-probe an unidentified save dump:
gbakit save probe mystery_dump.sav

# Machine-readable output with candidate scores:
gbakit save probe mystery_dump.sav --json

2. gbakit save info <file.sav> [--json]

Inspects save geometry, raw size, canonical chip size, trailing padding status, uniform padding fill byte (0x00 or 0xFF), active slots, and checksum validation status per slot.

# Inspect save geometry and slot integrity:
gbakit save info path/to/save.sav

3. gbakit save trim <file.sav> [-o <out.sav>] [--force] [--size <bytes>] [--game <code>]

Safely trims flat emulator padding down to canonical cartridge hardware capacity with 1:1 hardware fidelity. Built-in safety guards abort if non-padding bytes are detected beyond the canonical boundary unless --force is specified.

# Automatically detect geometry and strip emulator padding:
gbakit save trim padded_dump.sav -o canonical_save.sav

# Specify explicit game code for geometry lookup:
gbakit save trim padded_dump.sav -o canonical_save.sav --game BPEE

# Specify explicit canonical size in bytes (e.g. 512 bytes for EEPROM):
gbakit save trim padded_dump.sav -o canonical_save.sav --size 512
