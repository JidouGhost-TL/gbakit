1. Executive Summary & Overall Confidence

Overall confidence: HIGH for physical media, slot geometry, writer/reader architecture, and checksum. MEDIUM/LOW for semantic (gameplay) names of individual payload fields.

Proven by both decompiled code AND .sav bytes (verified):

  • Media is 32 KiB SRAM at 0x0E000000, 8-bit byte-copy I/O, fill 0xFF, no SDK tag, no Flash command sequence and no EEPROM/DMA3 path (Section 3, 4).
  • The file is 10 contiguous, non-overlapping, independently checksummed segments ("slots" 0–9) at offsets 0x0000, 0x0244, 0x0488, 0x06CC, 0x0910, 0x0B54, 0x0D98, 0x0DB8, 0x160C, 0x1650 with sizes 580, 580, 580, 580, 580, 580, 32, 2132, 68, 4 bytes, ending at 0x1654; the rest (0x1654–0x8000) is unused 0xFF.
  • Every slot begins with a u16_le CRC-16 (poly 0x1021, init 0xFFFF, final complement) over the remaining size-2 bytes. 18/18 populated slot instances verify in Python (all 10 in cap-01; 8 in cap-00, where slots 6/7 are erased 0xFF). See exact output in Section 4.
  • Writer FUN_080024c8, reader/verifier FUN_08002610, CRC FUN_0800458c, save-all serializer FUN_08002774, slot-7 updater FUN_0802693c, and load-validity FUN_08038b80 form the complete save path. All callers were traced in callgraph.json and confirmed in decompiled.c bodies (Section 3).

Static-only (code seen, RAM/ROM literal not in workspace): exact ROM values of the size/offset tables, CRC seed literal, CRC table base, and per-slot RAM buffer addresses — the Ghidra output leaves these as unresolved _DAT_08002xxx / unrecovered jumptables. Geometry and the CRC seed were instead proven from the .sav bytes (Sections 2, 4), so these gaps do not lower the HIGH confidence for the on-disk format.

Unknown / hypothesis: gameplay meanings of slot payload fields (e.g. slot0 byte at +2, the a8 a9 a7 af bytes at +10, slot7 counters/flags). These are labelled HYPOTHESIS/UNKNOWN in the field map and are not presented as facts.

Counts: saves/ holds 2 distinct 32768-byte snapshots (the packet's "6 total / profile" line refers to the wider cohort probe, not files present here). Diff cap-00→cap-01 is exactly 2164 bytes, all inside 0x0D98–0x160B (slots 6+7), matching a slot-6/7 write between captures.

Redundancy & selection rule: there is no primary/backup mirroring and no generation/sequence counter. No slot duplicates another's payload (slots 0–5 differ; 6–9 are structurally distinct), and no counter field was found — the only sequence-like bytes are slot6's fixed 0..29 sentinel (a format-integrity pattern, not a generation counter) and the per-slot byte 0xE4+i at +14 in slots 0–5 (a static slot index, constant across both caps). Validity is per-slot CRC (reader retry <3). The only multi-slot selection logic recovered is FUN_08038b80: read slot6 and slot7, return 0 if both valid, 1 if exactly one valid, 2 if both invalid. How its (jumptable-dispatched, caller-less) caller acts on 1 is unknown. In cap-00 slots 6/7 are erased 0xFF (stored CRC 0xFFFF ≠ computed), so FUN_08038b80 would return 2 for that snapshot; in cap-01 it returns 0. Whether cap-00 is an interrupted save or a deliberate partial state cannot be decided from the two files alone.

3. Save Writer, Reader & Caller-Chain Architecture

How callers were mapped (method, applied to every row below): (1) start from the 4 MMIO seeds in save_related_functions.c; (2) expand 2-hop callers / 1-hop callees; (3) cross-check every edge in callgraph.json (148 nodes); (4) open the full body in decompiled.c and confirm the call, its argument (slot index), and any RAM mutation before the flush. Edges present in the graph but contradicted by the body were rejected; the two "MMIO-seed" div/mod helpers were rejected as false seeds (below).

3.1 Low-level hardware I/O

  • FUN_0805481c(src, 0x0E000000+off, len) — SRAM write. Sets wait-state *_DAT_08054854 & _DAT_08054858 | 3, then byte-wise *dest++ = *src++. Byte access is mandatory on the 8-bit SRAM bus; this is the definitive media proof.
  • FUN_080547b8(0x0E000000+off, dest, len) — SRAM read. Copies a copy-routine onto the stack (SRAM timing-safe execution) and calls FUN_08054934.
  • FUN_0805488c(src, 0x0E000000+off, len) — SRAM verify/readback, same stack-routine pattern. The writer retries write+verify up to 5 times.
  • FUN_08054774 — BIOS SWI 0x0B (CpuSet/memcpy), used to zero/copy RAM slot buffers before flushing (FUN_08002748, FUN_08002774, FUN_08005098). FUN_08054770 is SWI 0x0C (division) — not save I/O.
  • False seeds excluded: FUN_080549fc (signed remainder) and FUN_08054b44 (unsigned remainder) are arithmetic helpers mislabelled as MMIO seeds in the seed file; they touch no save address and have no save callers. No Flash 0x5555/0x2AAA sequence and no EEPROM DMA3 (0x040000D4) path exists in the corpus.

3.2 Writer / reader / checksum

  • FUN_080024c8(slot) — writer. slot & 0xFF; aborts if *(byte*)(_DAT_08002504+_DAT_08002508) & 4. For slot < 10 it dispatches through an unrecovered jumptable (_DAT_08002510) — this is where the per-slot RAM source pointer (unaff_r5) and presumably the CRC-storing step are set; the generic tail computes size = *(u16*)(slot*2 + _DAT_0800250c), offset = Σ sizes[0..slot-1] (table _DAT_080025ec), then FUN_0805481c(r5, 0x0E000000+offset, size) + FUN_0805488c verify, retry < 5, result 0=ok / 1=fail returned via jumptable. Callers: 0x08002774, 0x0802693c (callgraph + bodies agree).
  • FUN_08002610(slot) — reader/verifier. Same size/offset computation (tables _DAT_0800265c/_DAT_08002714), FUN_080547b8(0x0E000000+offset, unaff_r8, size), then compares first u16 (*unaff_r8) against FUN_0800458c(size-2, unaff_r8+1) — note unaff_r8 is short*, so +1 is byte +2, i.e. CRC covers everything after the stored CRC. Retry < 3. Slot-6 special case: after CRC passes and slot == 6, it additionally checks 30 bytes equal 0,1,…,29 (while (uVar8 = abStack_42[uVar8]+1, uVar8 < 0x1E) if (abStack_42[uVar8] != uVar8) fail). Returns 0=ok / 1=fail. Sole caller: 0x08038b80.
  • FUN_0800458c(len, ptr) — CRC-16 (Section 4). Sole save caller: FUN_08002610. (FUN_0800452c, called by FUN_08023594/235d0, is a trailing-zero count, not the CRC.)
  • FUN_08038b80() — load-validity selector. FUN_08002610(6) and FUN_08002610(7) → 0 both valid, 1 exactly one valid, 2 both invalid. No callers in callgraph (entry via unrecovered jumptable).

3.3 Serializers / mutators — every caller chain

  1. FUN_08002774(char arg) — save-all (no callgraph callers; jumptable entry). Chain: FUN_08002774 → FUN_08005098(i) → FUN_080024c8(i) for i=0..5; if arg != 0: FUN_080024c8(6), CpuSet-prep, FUN_080024c8(7); then cleared-buffer FUN_080024c8(8); FUN_08002748(); FUN_080024c8(9); FUN_08026b04() (CpuSet 0x122 words to a RAM buffer); FUN_080024c8(0) again; if arg != 0: FUN_08026acc(); FUN_080024c8(7) again. RAM mutations before flush: slots 0–5 via FUN_08005098, slot8 zeroed (uStack_16=0 + CpuSet), slot9 via FUN_08002748, slot7 second pass via FUN_08026acc. The double write of slots 0 and 7 is observed in code, reason unknown (likely a final consistency pass — hypothesis).
  2. FUN_08005098(slot) — prep slots 0–5 (caller: FUN_08002774 only). Loads ROM data via func_0x08054c04 (6- and 7-byte buffers), zeroes the slot RAM buffer (*(int*)(slot*4+table)) via CpuSet, sets *(buf+3) = 0x19, takes per-slot byte auStack_1c[slot], copies a NUL-terminated buffer to buf+10. On disk this matches: file +3 = 0x19 (slots 1–5), +10..13 = a8 a9 a7 af, +14 = 0xE4+slot. Slot0's +3 = 0x13 differs, so slot0 is modified after prep (or prepped differently) — static-only caveat.
  3. FUN_08002748() — prep slot9 (caller: FUN_08002774). Zeroes buffer via CpuSet, sets *(buf+2) = 1. On disk: slot9 payload 01 00 in both caps.
  4. FUN_0802693c() — progression update, flush slot7 only (no callgraph callers). Five-group loop: FUN_08003078(0, 0xF) / FUN_080235d0(group, id) / FUN_08023594(group, id) table lookups, then FUN_080058d8(id, 0) increments, building a 26-u32 local bitfield (auStack_94); ends with the single call FUN_080024c8(7). This is the only writer chain that touches slot7 alone, and it is the natural explanation for cap-00 (slots 6/7 erased) → cap-01 (slots 6/7 populated) — although FUN_08002774 also writes slot7, so attribution of the cap difference to this specific caller is CONFIRMED_STATIC for the chain, HYPOTHESIS for the capture attribution.
  5. FUN_08026acc() — slot7 re-prep (caller: FUN_08002774 only). Zeroes *(DAT+4), loops 0x42 = 66 u16 entries calling FUN_080058d8(id, 0); the caller then re-flushes slot7.
  6. FUN_080058d8(id, flag) — counter/flag mutator (callers: FUN_0802693c, FUN_08026acc). Indexes a RAM struct by id: increments a byte counter (capped at 99), increments one of two sub-counters (+0x0C vs +0x24 table, selected by a >>4 < 3 test), increments a global at +4, and if flag != 0 records id into a history ring at +0x3C. This RAM struct is (part of) the slot7 buffer flushed afterwards; its exact RAM base is a _DAT, unresolved.

No other function in the 148-function corpus calls the writer, reader, or SRAM primitives (verified by full callgraph scan: FUN_080024c8 callers = {08002774, 0802693c}, FUN_08002610 callers = {08038b80}, SRAM primitives have no other callers).

4. Magic Signatures & Checksum / Integrity Algorithm

4.1 Checksum

Decompiled proof (FUN_0800458c, ghidra/decompiled.c:1785):

uVar1 = _DAT_080045c4;                                   // seed (literal unresolved)
while (param_1 = param_1 + -1, -1 < param_1) {
  uVar1 = (uVar1 << 8 ^ *(ushort*)((uVar1 >> 8 ^ (uint)*param_2) * 2 + _DAT_080045c8)) & 0xffff;
  param_2 = param_2 + 1;
}
return ~uVar1 & 0xffff;                                  // (via unrecovered jumptable)

This is an MSB-first table CRC-16, polynomial 0x1021 (the only polynomial whose table reproduces the stored values at the geometrically-derived lengths). The seed literal _DAT_080045c4 is not in the workspace; brute-force over init ∈ {0, 0xFFFF, 0x1D0F, …} × final-xor ∈ {0, 0xFFFF} shows init 0xFFFF with the code's final complement is the unique combination matching all 18 valid slot instances at their true lengths (other combinations match only spuriously at wrong lengths). Formula, as implemented and verified:

crc = 0xFFFF
for b in payload:  crc = ((crc << 8) ^ T[((crc >> 8) ^ b) & 0xFF]) & 0xFFFF   # T = poly-0x1021 MSB table
stored_u16_le(slot+0) = (~crc) & 0xFFFF        # covers slot+2 .. slot+size-1

Stored offset: slot+0, size 2, little-endian. Covered range: slot+2 to slot+size-1 inclusive. Reader proof: FUN_08002610 compares *buf vs FUN_0800458c(size-2, buf+2), retry <3; writer verify is readback (FUN_0805488c), retry <5.

4.2 Magic signatures

  • Slot6 sentinel (verified in code and sav): payload 00 01 02 … 1D (30 bytes) at 0x0D9A–0x0DB7 in cap-01. FUN_08002610 explicitly validates byte[i] == i for i < 0x1E when slot == 6. This is a genuine integrity signature, not ASCII.
  • a8 a9 a7 af at slot +10 (slots 0–5, both caps): constant across all six records, written in the FUN_08005098 prep path (copy to buf+10). It is not ASCII and no code compares it on load, so it is recorded as HYPOTHESIS signature/data, verified_in_code=false in the JSON. Do not treat it as a proven magic.
  • No ASCII magic exists: packet ascii_magic_strings: [] and a byte scan agree (the 55 AA at 0x0000 is slot0's stored CRC 0xAA55, not a magic — proven by the CRC match above).

6. Save Fuzzing & Counterfactual Verification Plan

No paired .ss save-states exist in this workspace (states/ is empty), so every test below is a prediction to run when states are available: load the state, replace the .sav, cold-reload, and observe UI/RAM. Checksum repair everywhere means: recompute CRC-16 (poly 0x1021, init 0xFFFF, final complement, Section 4) over slot+2..slot+size-1 and store u16_le at slot+0. A mutation without repair must be rejected by FUN_08002610 (retry <3 then fail) — that rejection is itself the first observable.
