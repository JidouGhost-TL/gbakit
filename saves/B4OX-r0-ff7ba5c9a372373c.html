1. Executive Summary & Overall Confidence

Overall confidence: MEDIUM.

Proven by both decompiled code and .sav bytes (CONFIRMED_VERIFIED):

  • The active save is a single contiguous 15768-byte (0x3D98) image at flash offset 0: a 24-byte (0x18) global header followed by four independent 3936-byte (0xF60) slots. The rest of the 64 KiB flash (0x3D98..0xFFFF) is erased 0xFF in both samples.
  • Integrity is a plain 16-bit byte sum (sum16). FUN_08054f18 at 0x08054f18 sums unsigned bytes modulo 65536. It protects the 24-byte header (stored at header +0x00, recomputed by FUN_08054f6c at 0x08054f6c) and each 3936-byte slot separately (stored at header +0x02 + i*2, computed by FUN_08054f44 at 0x08054f44). Python recomputation matches every stored value in both files — all 2 header checksums and all 8 slot checksums (Section 4).
  • The load-checked magic is the 4-byte ASCII A2M7 at header offset 0x0A (written by FUN_08054f88 at 0x08054f88, compared by FUN_08054ec8 at 0x08054ec8). The string WAFFY at slot +0x5A0 is a default name string written by FUN_08054a8c at 0x08054a8c, not a load-checked magic.
  • Default slot contents are fully reconstructed for the nonzero fields: 0x640 (1600) at slot +0x0C, slot index at +0x10, WAFFY at +0x5A0, a 20-bit bitfield at +0xF0C (46 3F F0 E2 C2), and 0xFF sentinel bytes at stride 4 from slot +0xF4F. The bitfield byte encoding was independently reconstructed in Python from the 20 FUN_080356d8 call sites and matches exactly.
  • The only difference between the two captures is 3 bytes: header byte +0x13 (0x00 -> 0xAB) and the resulting header checksum (0x067B -> 0x0726, delta exactly +0xAB). This matches the packet cold-reload probe: mutating offset 0x0 breaks integrity and the game reverts to blank and rewrites the save.

Static-only (CONFIRMED_STATIC, code read but no differing .sav sample to exercise it):

  • The full writer/reader architecture: boot load at FUN_08054e50 (0x08054e50), blank reset at FUN_08054fbc (0x08054fbc), header-only flush at FUN_08054d74 (0x08054d74), sector-buffered flash read/write at FUN_08058bc4/FUN_08058cd4 (0x08058bc4/0x08058cd4), and the AgbFlash-style driver cluster at 0x0806dcb0..0x0806e3b8.

Open (HYPOTHESIS / UNKNOWN):

  • The absolute RAM mirror address. Every _DAT_080xxxxx literal in ghidra/decompiled.c is named by its literal-pool address; its value is not present in the corpus. ram_addr is therefore null in save-format.json. Only the layout (header at buffer start, slot i at +0x18 + i*0xF60) and the slot-0-relative pointer (_DAT_08055010, header at slot0 -0x18) are known.
  • The meaning and writer of header byte +0x13, the upstream trigger of FUN_08054d74, and any gameplay (non-reset) slot writer. No textual or callgraph caller exists for them; entry is through an unrecovered jumptable.
  • Most slot payload bytes are zero in both near-blank samples and remain unmapped.

3. Save Writer, Reader & Caller-Chain Architecture

How callers were mapped: every function was located by exhaustive textual search of ghidra/decompiled.c for both FUN_080xxxxx definitions and func_0x080xxxxx call sites (Ghidra emits the latter for calls through recovered thunks), then cross-checked against ghidra/callgraph.json. The callgraph is incomplete for this cluster — for example it lists FUN_08058bc4 at 0x08058bc4 with no callees beyond FUN_08055794/FUN_08055870, and FUN_08054f6c with only FUN_08054fbc as caller, while the text shows the additional func_0x08054f6c() call in FUN_08054d74. 3.4 Caller chains (summary)

  1. Boot/load: FUN_0805b0d0 → FUN_08054a60 → FUN_08054a8c (default slot RAM) + FUN_08054e50 → FUN_08058b78 → FUN_0806e18c → FUN_0806dcb0; read via FUN_08058bc4 → FUN_08058e0c → FUN_0806df04/FUN_0806e068; validate via FUN_08054ec8 + per-slot FUN_08054f18.
  2. Blank reset (any load failure): FUN_08054e50 → FUN_08054fbc → FUN_08054f88 + 4× (memset, FUN_08054a8c, FUN_08054f44) → FUN_08054f6c → FUN_08058cd4 → FUN_08058e0c + FUN_08058e68 → FUN_0806e100 → FUN_0806dfd0.
  3. Header-only flush (trigger unknown): unknown jumptable entry → FUN_08054d74 → FUN_08054f6c → FUN_08058cd4 (24 bytes). Before this flush, the unknown caller must have mutated the RAM header (the observed case: byte +0x13); FUN_08054f6c then repairs the checksum at +0x00. No slot bytes are touched by this chain, matching the cap-00 → cap-01 diff exactly.
  4. No gameplay slot-flush chain exists in the traced corpus: the only FUN_08058cd4 call sites are FUN_08054d74 (header) and FUN_08054fbc (full reset). A normal in-game slot save either goes through an untraced jumptable path or reuses the full-image write; this is an open question, not a gap filled by invention.

4.2 Checksum algorithm (exact)

One primitive protects everything, FUN_08054f18 at 0x08054f18 (ghidra/decompiled.c:1678-1697):

short FUN_08054f18(int buf, uint len) {
    short s = 0; uint i = 0;
    if ((len & 0xffff) != 0)
        do { s = s + (ushort)*(byte *)(buf + i); i = (i + 1) & 0xffff; }
        while (i < (len & 0xffff));
    return s;
}
  • Algorithm class: sum16 — sum of unsigned bytes, modulo 65536. No seed, no complement, no XOR, no CRC, no word-wise addition. The stored field is the low 16 bits, written little-endian.
  • Header instance: FUN_08054f6c at 0x08054f6c zeroes the stored field first (*hdr = 0), then stores FUN_08054f18(hdr, 0x18). Covered range is therefore header bytes [0x00, 0x18) with bytes 0x00..0x01 taken as zero — equivalently the sum of header bytes 0x02..0x17. Stored at file offset 0x00, size 2.
  • Slot instance: FUN_08054f44 at 0x08054f44 stores FUN_08054f18(slot, 0xF60) at header + 2 + index*2. Covered range is the whole 3936-byte slot. Stored at file offsets 0x02, 0x04, 0x06, 0x08 for slots 0..3 (contiguous 8-byte array at header +0x02). Because the header checksum covers the slot-checksum array, any slot repair must also repair the header checksum (order in FUN_08054fbc: slots first via FUN_08054f44, header last via FUN_08054f6c).
  • Verification on load: FUN_08054ec8 recomputes the header sum the same way (save stored value, zero, recompute, compare) and FUN_08054e50 recomputes each slot sum and compares against header+2+i*2.

A brute-force search over all contiguous byte intervals in the active save also independently located the header checksum: the only interval family matching both files is [0x02, 0x14) up to trailing zero bytes [0x02, 0x24), which is exactly the code-covered [0x00,0x18) with the field zeroed — the code and the bytes agree, and zero padding is the only ambiguity.

6. Save Fuzzing & Counterfactual Verification Plan

No paired .ss save states exist in this workspace (states/ is empty), so the packet's state-paired reload is replaced with cold .sav reload: place a mutated .sav next to the ROM in an emulator with Flash 512K save type, boot, and observe (a) whether the save is accepted or reverted to blank, (b) whether the .sav file is rewritten on boot/next save, and (c) the in-game value tied to the mutated field. Checksum repair procedure for a mutated covered byte: recompute the slot sum (sum16 over the slot's 0xF60 bytes) into header+2+i*2 if a slot byte changed, then recompute the header sum with the checksum field zeroed into header+0x00. Mutations that predict "blank reset" are expected to produce the packet probe signature: boot to a blank/new save, visual delta on load, and the .sav rewritten to the default image (header checksum 0x067B pattern, all slots default).
