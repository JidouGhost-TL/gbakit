1. Executive Summary & Overall Confidence

Overall confidence: MEDIUM.

Proven by both decompiled code AND .sav bytes (CONFIRMED_VERIFIED):

  • The save medium is a 64-Kbit (8,192-byte) serial EEPROM accessed through DMA3 at 0x0D000000, in 8-byte blocks. The low-level bit-bang/DMA driver, block read/write wrappers, and verify-retry logic are fully traced (Section 3).
  • The 16-byte global header at file offset 0x0000 starts with the 8-byte ASCII magic 0000EISA and ends with a 16-bit additive checksum at 0x000E such that the sum of the eight big-endian u16 words in the header is 0 mod 65536. This was recomputed in Python against both sample saves and matches exactly (Section 4). The little-endian interpretation fails (0x01FE), which independently confirms the driver's MSB-first bit assembly.
  • The EEPROM is partitioned into one 16-byte header plus four 2,040-byte save slots, followed by 16 unused bytes. The geometry arithmetic in code (slot * 0xFF + 2 blocks, 0xFF blocks per slot) reproduces the exact non-0xFF spans observed in both .sav files.

Static-only (CONFIRMED_STATIC, code-proven but not exercisable on the samples):

  • Each 2,040-byte slot is validated by the same additive u16 sum over 0x7F8 bytes; a valid slot must sum to zero, so its final u16 is the negated partial sum.
  • On a blank/invalid header the game writes a default header and writes only the first 5 blocks (40 zero bytes) of each slot. Both samples are exactly in this freshly-initialised state: every slot fails its checksum (0xFC18) and is therefore treated as empty.

Open / unknown:

  • No populated slot exists in the corpus. Both saves contain only the initialised header and zero stubs; all gameplay fields inside the 2,040-byte slot payloads are UNKNOWN. Any field map inside a slot would be fabrication.
  • No full-slot gameplay writer was recovered among the 260 decompiled functions. The only slot writes traced are the 40-byte initialisation stubs. The full-slot flush presumably calls the same block writer with (slot*0xFF+2, 0xFF, buffer), but no such static call site survives Ghidra's unrecovered-jumptable tails. This is stated plainly rather than invented.
  • Exact EWRAM addresses of the RAM mirrors cannot be resolved: the decompilation references them only through unresolved ROM literal pointers (_DAT_0803xxxx). RAM addresses are therefore reported as null/unresolved.
  • Header bytes 0x08-0x0D changed between the two captures in a checksum-compensating way, but their semantic meaning (counters vs. settings) is a hypothesis only.

3. Save Writer, Reader & Caller-Chain Architecture

All addresses are ROM addresses (0x08xxxxxx). The call graph in ghidra/callgraph.json is incomplete for this cluster because most functions end in UNRECOVERED_JUMPTABLE tails; caller mapping below therefore combines callgraph.json edges with direct func_0x... call sites in ghidra/decompiled.c (the method used for every caller listed: text search for the callee's func_0x name, then reading the enclosing function body).

3.1 Low-level hardware I/O driver (EEPROM via DMA3)

FUN_0804c9d4 — DMA3 transfer primitive

  • Signature: FUN_0804c9d4(src, dst, count_halfwords).
  • Saves a timing/IRQ global, masks a control register with a timing value taken from the EEPROM config struct (*(u16*)(cfg+6)), writes src/dst to the DMA3 source/destination registers and count | 0x80000000 (DMA enable, 16-bit unit) to the DMA3 control register (the 0x040000D4 register block supplied in PACKET.md; the literal pointers are unresolved _DAT_0804ca44/48/4c), then busy-waits on the DMA busy bit (0x8000 of the control high halfword) and restores the saved global.
  • Callers: FUN_0804ca54, FUN_0804cb18 (both in callgraph.json and in the decompiled bodies).

FUN_0804ca54 — EEPROM read one 8-byte block

  • Signature: FUN_0804ca54(block_addr, ram_dst). Returns a status global via the jumptable tail.
  • Masks the address to 16 bits and rejects block_addr >= *(u16*)(cfg+4) (the device block count, 1,024 for this 8 KB part).
  • Builds the read command bitstream on the stack, most-significant bit first: the address bits (count = *(u8*)(cfg+8), the device address-bit count; 10 bits address 1,024 blocks — the exact config value lives in ROM and is not in this workspace, so the bit count is a strongly-supported inference from the 8,192-byte size, marked accordingly in the JSON), followed by the two leading 1 bits written explicitly (*puVar5 = 1; puVar5[-1] = 1).
  • DMAs addr_bits + 3 halfwords to 0x0D000000, then DMAs 0x44 (68) halfwords back from 0x0D000000 (64 data bits plus turn-around/dummy bits).
  • Reassembles the four destination u16s MSB-first (uVar4 = uVar4 << 1 | *puVar5 & 1, 16 iterations each), storing them from ram_dst+6 downwards. This MSB-first assembly is why the on-disk checksum verifies big-endian (Section 4).
  • Sole caller: FUN_080380cc (block-read loop) and FUN_0804cc78 (verify) — see callgraph.json: callers 0x0804cc78 only at this level; the block loop call is visible in the FUN_080380cc body.

FUN_0804cb18 — EEPROM write one 8-byte block

  • Signature: FUN_0804cb18(block_addr, ram_src_u16x4, wait_flag).
  • Expands each of the four source u16s into 16 stack bits (MSB-first), appends the address bits, and prefixes the bits 0 then 1 (the write opcode pair, mirror image of the read's 1,1).
  • DMAs addr_bits + 0x43 (67) halfwords to 0x0D000000 — 64 data bits plus address/command overhead.
  • Then polls the EEPROM busy line by reading 0x0D000000 & 1, using a timer global (_DAT_0804cc04, wrap 0xE4, budget 0x88) to time out; the wait_flag parameter controls whether it waits for the ready edge. This is the serial EEPROM's write-cycle wait.
  • Caller: FUN_0804cd10 only (callgraph.json and body).

FUN_0804cc78 — verify one block after write

  • Reads the block back via FUN_0804ca54 into a stack buffer and compares all four u16s against the source; returns 0 on match, 0x8000 on the first mismatch.
  • Caller: FUN_0804cd48 only.

FUN_0804cd10 — write wrapper (device-type gate)

  • If the config device-type word is not 0x200 (i.e. not the small 512-byte EEPROM geometry), it calls FUN_0804cb18(addr, data, 0) and returns its status. For this title the non-0x200 path is the operative one.
  • Caller: FUN_0804cd48 only.

FUN_0804cd48 — write-with-verify, retry ×3

  • Up to three attempts of FUN_0804cd10 + (on success) FUN_0804cc78 verify; breaks on a verified write, otherwise returns the error status. This is the only entry point the block layer uses for writes, so every byte that reaches the EEPROM is write-verified up to three times.
  • Caller: FUN_080380fc only (visible in its body; callgraph.json lists no caller for 0x0804cd48 because the block functions' own edges were not recovered — the textual call site is decisive).

FUN_0804c98c — EEPROM timing/type configuration

  • Called as FUN_0804c98c(0x40) from the bus-lock function; the 4 / 0x40 / other branches select different timing globals. Treated as the SDK's EEPROM access-timing setup applied before a block transfer burst.

FUN_0803812c / FUN_0803815c — bus lock / unlock

  • FUN_0803812c saves a control global, applies a mask ((short)_DAT_08038158), zeroes a control halfword, and calls FUN_0804c98c(0x40). FUN_0803815c restores the saved global. Every multi-block read/write burst is bracketed by this pair, consistent with protecting the DMA3/EEPROM bus from concurrent users.

3.2 Block layer

FUN_080380cc — read N blocks

FUN_080380cc(start_block, block_count, ram_dst): locks the bus, loops FUN_0804ca54(block, dst); dst += 8; block++, unlocks. Textual callers (mapped by searching func_0x080380cc):

  • FUN_08037f7c — load one full slot: FUN_080380cc(slot*0xFF+2, 0xFF, *(mgr+0x10)).
  • FUN_08037fb4 — read current header into a stack buffer for comparison.
  • FUN_08038074 — read header for validation.

FUN_080380fc — write N blocks

Identical loop over FUN_0804cd48. Textual callers:

  • FUN_08037cec — initialisation: FUN_080380fc(block, 5, buf) for block = 2, 257, 512, 767 (first 40 bytes of each slot).
  • FUN_08038034 — write the default header (blocks 0-1).
  • FUN_08037fb4 — flush the RAM header mirror (blocks 0-1).

3.3 Checksum, header and slot managers

FUN_08038010 — additive u16 checksum

FUN_08038010(short *buf, uint byte_len): sums byte_len/2 consecutive u16s into a 16-bit accumulator and returns it. This is the sole integrity primitive; there is no CRC, XOR-fold, or complement table anywhere in the traced save cluster. Callers: FUN_08037f4c, FUN_08037fb4, and inline open-coded copies of the same loop in FUN_08038034 and FUN_08038074.

FUN_08038034 — create default header

Copies a 16-byte ROM template (FUN_08027b5c, a memcpy, copies 0x10 bytes from _DAT_08038070) into the header RAM mirror (_DAT_0803806c), sums its eight u16s, stores -sum into word 7 (byte offset 0x0E), and writes blocks 0-1 via FUN_080380fc(0,2,...). Because the template's word 7 is summed before being overwritten, the template must carry 0x0000 there for the stored total to be zero; the observed saves satisfy sum == 0 (Section 4). Sole caller: FUN_08037cec (blank-header path).

FUN_08038074 — validate header

Reads blocks 0-1 into a RAM buffer, sums the eight u16s; if the sum is zero it byte-compares the first 8 bytes against the expected magic string (two 8-byte operands iRam080380c4/iRam080380c8, one being the freshly read bytes and the other the ROM constant). Returns 1 only if both the checksum and the magic match. Sole caller: FUN_08037cec.

FUN_08037fb4 — recompute checksum and flush header

Reads the on-EEPROM header into a stack array; zeroes word 7 of the RAM header mirror (_DAT_08037ff4, offset +0xE), computes FUN_08038010(mirror, 0x10), stores the negated sum at +0xE; then, only if the mirror's first u32 equals the EEPROM header's first u32 (the 0000 half of the magic), writes the mirror back with FUN_080380fc(0,2,...) and returns 1. Sole caller: FUN_0802417c.

How the caller mutates RAM before flushing: FUN_0802417c runs FUN_080450a0(*(mgr+0xC)) (selects/applies a byte-sized global setting), then FUN_08037d3c, then IRQ-ish helpers FUN_08041390/FUN_0804139c bracketing the flush. FUN_08037d3c writes two bytes into the manager struct — *(u8*)(mgr+10) = FUN_080450dc() (a getter returning a byte global, the same value family set by FUN_080450a0) and *(u8*)(mgr+11) = 1 — immediately before FUN_08037fb4 recomputes the header checksum and writes the header. This chain is therefore the traced path by which a settings/config change reaches the EEPROM header, and it explains the PACKET.md mutation probe: mutating header byte 0x08 leaves the magic's first word intact, so this flush path can rewrite/repair the header rather than reverting to blank. Mapping manager offsets +10/+11 onto .sav bytes 0x0A/0x0B is not proven (the manager base pointer is unresolved), so those two header bytes remain HYPOTHESIS in the field map.

FUN_08037f7c — load one slot

FUN_080380cc(slot*0xFF+2, 0xFF, *(mgr+0x10)): reads 255 blocks (2,040 bytes) into the shared heap work buffer. Caller: FUN_08037c70 only.

FUN_08037f4c — validate one slot

Computes FUN_08038010(*(mgr+0x10), 0x7F8) and stores sum == 0 as a boolean at mgr+0xB4+slot. Caller: FUN_08037c70 only.

FUN_08037d54 — zero the slot work buffer

FUN_08027af0(*(mgr+0x10), 0, 0x7F8) (a memset). Caller: FUN_08037cec only.

FUN_08037c70 — enumerate all four slots at boot

For each slot 0-3: loads it (FUN_08037f7c) and validates it (FUN_08037f4c); if the per-slot valid flag (mgr+0xB4+slot) is zero it zeroes that slot's 40-byte (0x28) descriptor with FUN_08027af0, otherwise it records the buffer pointer at mgr+0xBC, clears mgr+0xC0, and calls the out-of-cluster descriptor parser func_0x0801bbac(descriptor) (not among the 260 bodies; its role — filling the menu descriptor from the loaded buffer — is inferred from its single argument and position, and is labelled as such). Sole caller: FUN_08037cec.

FUN_08037cec — save-system boot initialisation

Allocates the zeroed 2,040-byte work buffer (FUN_0802798c(0x7F8), a malloc-and-zero helper) and stores it at mgr+0x10. Validates the header (FUN_08038074); on failure it creates the default header (FUN_08038034), zeroes the work buffer (FUN_08037d54), and writes the first 5 blocks of each of the four slots from the zeroed buffer. It then applies the byte setting (FUN_080450a0(*(u8*)(mgr+10))) and enumerates the slots (FUN_08037c70). No caller is listed in callgraph.json (boot entry via an unrecovered jumptable); it is the root of the save-system chain.

This is the largest open question (Section 6 of the JSON).

4. Magic Signatures & Checksum / Integrity Algorithm

4.1 Magic signature

  • Bytes (file offset 0x00, 8 bytes): 30 30 30 30 45 49 53 41 — ASCII 0000EISA.
  • Verified in code: FUN_08038074 byte-compares the first 8 header bytes after a successful checksum, and FUN_08037fb4 compares the first u32 (0000) before allowing a header flush.
  • Verified in .sav: present verbatim at offset 0 of both samples.
  • Note the byte order: read as ASCII it is 0000EISA (the game code ASIE byte-reversed within its word, a side effect of the MSB-first EEPROM bit order); no other ASCII magic exists in either file.

4.2 Checksum algorithm

  • Algorithm: 16-bit ones'-complement-style additive checksum. Sum all u16 words of the covered region modulo 65536; the stored final word is the two's-complement negation of the partial sum, so the total including the stored word is exactly 0x0000.
  • Word order: big-endian relative to the .sav byte stream. The driver assembles each u16 MSB-first (uVar4 = uVar4 << 1 | bit), so the first byte of each pair is the high byte in the file image. The little-endian sum of the sample headers is 0x01FE ≠ 0, while the big-endian sum is 0x0000 — decisive.
  • Formula: stored = (- Σ words[0..n-2]) mod 65536; validity: Σ words[0..n-1] mod 65536 == 0.
  • Decompiled proof:
  • FUN_08038010: sVar1 = 0; do { sVar1 += *param_1++; } while (--count); return sVar1; over byte_len/2 words.
  • FUN_08038034 (header creation): sums the eight header words, then _DAT_0803806c[7] = -sVar1;.
  • FUN_08037fb4 (header flush): *(u16*)(mirror+0xE) = 0; sVar2 = FUN_08038010(mirror, 0x10); *(short*)(mirror+0xE) = -sVar2;.
  • FUN_08038074 (header validation): open-coded sum of eight words, valid iff sVar1 == 0.
  • FUN_08037f4c (slot validation): *(bool*)(mgr+0xB4+slot) = (FUN_08038010(buf, 0x7F8) == 0);.

Interpretation:

  • The header checksum is CONFIRMED_VERIFIED on both independent samples. The inter-sample diff (byte 0x08: 07→06, byte 0x0C: 00→01) exactly cancels in the BE sum (-0x0100 + 0x0100 = 0), leaving the stored checksum 0xFF80 unchanged — precisely the behaviour expected when a header field pair changes and the checksum is recomputed by FUN_08037fb4, and it matches the PACKET.md probe result (integrity_check_confirmed: true, mutation at 0x08 did not revert to blank).

6. Save Fuzzing & Counterfactual Verification Plan

No paired .ss save states ship in this workspace (states/ is empty), so every test below is specified as: mutate the .sav, repair checksums where noted, boot/load in an emulator, and observe. Predictions derive strictly from the traced code.

Checksum repair recipes (prerequisite for most tests):

  • Header: set bytes 0x0E-0x0F to the BE u16 value (-(sum of BE u16 words at 0x00-0x0C)) & 0xFFFF.
  • Slot s: set the final two bytes at slot_base + 0x7F6 to the BE u16 value (-(sum of the first 1,019 BE u16 words)) & 0xFFFF, where slot_base is 0x0010 / 0x0808 / 0x1000 / 0x17F8.
