1. Executive Summary & Overall Confidence

Overall confidence: MEDIUM.

Proven by both code and .sav bytes (CONFIRMED_VERIFIED):

  • The save medium is 32 KiB SRAM (SRAM 256K); every .sav is exactly 32768 bytes with erased fill 0xFF.
  • There is one logical save, stored as 59 chunks (descriptor table stride 0x18, span 0x588 = 59 × 24, loop bound 0x3B) written twice: a primary copy and a byte-identical backup copy at SRAM offset +0x3E00.
  • The populated snapshot contains the ASCII magic Hamtaro\0 at file offsets 0x200 (primary) and 0x4000 (backup), and the stored checksum pair 0x4D49 / 0xB2B6 satisfies 0xB2B6 == ~0x4D49 in both copies.
  • The blank snapshot is the erased state: only the 332-byte global header at offset 0x0000 was ever written (all zero); everything else is 0xFF. The game treats this as "no save" (magic test fails) and initialises a new save.

Proven by code only (CONFIRMED_STATIC):

  • The integrity algorithm is a 16-bit additive byte sum over the 59 chunk buffers with a ones'-complement shadow word (Section 4), recomputed by FUN_08002f84, validated by FUN_080038c0, and delta-repaired/flushed by FUN_08002fd8.
  • Boot/save orchestration lives in FUN_080038c0; new-game initialisation in FUN_08002434; sub-structure reset in FUN_08002634; slot/character selection in FUN_080031a0; play counters in FUN_0800327c; name/text rebuild in FUN_080034b0.

Open / not proven (HYPOTHESIS / UNKNOWN):

  • Exact checksum coverage cannot be recomputed from the .sav files alone. The 59-entry descriptor table (RAM pointer, size, SRAM offset per chunk) is ROM-resident; Ghidra left every table address as an unresolved _DAT_08003bf0-style placeholder and no ROM/data dump exists in this workspace. A plain byte sum over the whole populated SRAM span gives 0x5442, not the stored 0x4D49 (Section 4.3). The summed set is therefore a proper subset of the span (per-chunk buffers, excluding inter-chunk SRAM bytes), but the per-chunk boundaries are unrecoverable from the workspace. This is the main reason the grade is MEDIUM, not HIGH.
  • Absolute EWRAM/IWRAM addresses of the RAM save struct and its chunks are unknown (all _DAT_* placeholders unresolved). Field semantics beyond offsets/sizes (which counter is "days", which byte is a character id, etc.) are hypotheses from code shape only.
  • The MMIO-seed extraction in ghidra/save_related_functions.c over-matched: the FUN_080021c8 / FUN_0800223c / FUN_08002268 / FUN_0800227c wrappers and most of their callers are a bitfield/unlock-flag service (via FUN_0808b4d0 bit-test, FUN_0808b4f8 bit-set, FUN_0808b560 bit-clear, FUN_0808b6cc bit-range write), not save I/O. Real save I/O uses the SRAM copy routines at 0x080bbb00 / 0x080bbc38 / 0x080bbb64 / 0x080bbbd4 and the unresolved DMA/copy stub FUN_080bbc7c.

Copy selection rule (from FUN_080038c0, decompiled lines 2445–2544 of ghidra/decompiled.c):

  1. Load backup chunks (+0x3E00) into the canonical RAM struct, copy canonical → mirror RAM struct (FUN_0808c818), then load primary chunks into canonical RAM. (Load order inferred from the two FUN_080bbc7c loops; FUN_080bbc7c itself is an unresolved jump-table stub, so direction is CONFIRMED_STATIC, not byte-proven.)
  2. If the first string of both RAM structs differs from the magic (FUN_080bdb94 = strcmp, returns non-zero), call FUN_08002434 (new-save init), copy canonical → mirror, and write the global header block to SRAM with verify (FUN_080bbc38(..., 0x0E000000, 0x14C)).
  3. Validate each RAM copy: byte-sum over all 59 chunks must equal the u16 at struct +8, and struct +10 must equal its ones' complement. Results land in aiStack_28[0] (canonical/primary) and aiStack_28[1] (mirror/backup).
  4. If the selected copy is invalid but the other is valid, rebuild RAM from the valid copy and call FUN_08002fd8 to delta-repair and rewrite both SRAM copies. If both are invalid, re-initialise via FUN_08002434, write the global header, call FUN_08002268(0xF20) (flag service) and set 0x05000000 = 0x1F (display control; outside save geometry).

Redundancy verdict: full dual-copy mirroring of every chunk, no interleaving, no generation counter — classic "last valid copy wins, else rebuild" scheme.

4. Magic Signatures & Checksum / Integrity Algorithm

4.1 Magic signature

  • Bytes: 48 61 6D 74 61 72 6F 00 = ASCII Hamtaro\0, at struct offset +0x00 → file offsets 0x200 (primary) and 0x4000 (backup).
  • Code proof: FUN_080038c0 calls FUN_080bdb94 (word-optimised strcmp, ghidra/decompiled.c:13884) on both loaded RAM structs against a ROM string pointer; both must differ before a new save is created. The literal string itself lives in ROM (not dumped in this workspace), so the code-side byte identity is CONFIRMED_STATIC; the .sav-side bytes are CONFIRMED_VERIFIED.
  • Blank sample: offsets 0x200/0x4000 are 0xFF…, so the magic test fails on both copies — exactly the observed "no save" state.

4.2 Checksum algorithm (code-proven)

From FUN_08002f84 (ghidra/decompiled.c:1976), mirrored in FUN_080038c0 (lines 2445–2482) and FUN_08002fd8 (lines 2053–2078):

// for each of 59 chunks i:  ptr = desc[i].ram_ptr (+ struct-base delta), len = desc[i].size
u16 sum = 0;
for (i = 0; i < 59; i++) {
    u16 chunk_sum = 0;
    for (j = 0; j < desc[i].size; j++) chunk_sum += (u8)ptr[j];
    sum += chunk_sum;              // all arithmetic mod 2^16
}
struct[+8]  = sum;                 // u16 LE
struct[+10] = ~sum;                // u16 LE ones' complement

Validation is the pair test struct[+8] == sum && struct[+10] == (u16)~sum. FUN_08002fd8 never recomputes from scratch on the flush path; it adjusts incrementally: +8 += (ram_chunk_sum - sram_chunk_sum) per differing chunk, then +10 = ~+8 — algebraically identical if exactly the flushed chunks changed.

Stored location: struct +0x08 (2 bytes, LE) and struct +0x0A (2 bytes, LE) → file 0x208/0x20A (primary), 0x4008/0x400A (backup). Covered range: the union of the 59 chunk buffers — not a single contiguous file range, and explicitly excluding the checksum words' own chunk header semantics is unresolvable (see 4.3).

Every contiguous candidate fails (whole span 0x5442; excluding the 4 checksum bytes 0x5244; from +0x0C 0x4F78; head-only and suffix searches over all start/end pairs found no contiguous match). The covered set must be the 59 descriptor-delimited RAM buffers, whose sizes/offsets are ROM data absent from this workspace. The algorithm is therefore CONFIRMED_STATIC (three independent code sites agree) with the stored pair CONFIRMED_VERIFIED, and exact coverage is UNKNOWN. Any future dump of the descriptor table at _DAT_08003bf0 (ROM 0x08… address) closes this gap mechanically.

6. Save Fuzzing & Counterfactual Verification Plan
