1. Executive Summary & Overall Confidence

Overall confidence: MEDIUM.

Proven by both decompiled code and .sav bytes (CONFIRMED_VERIFIED):

  • Media is plain byte-addressed SRAM at 0x0E000000, 32 KiB (SRAM 256K), fill 0xFF, no SDK save tag string in the corpus metadata.
  • Layout is 3 slots × 4 identical copies × 908 bytes (0x38C), slot stride 0xE30 (3632 bytes), total used 0x2A90 (10896 bytes).
  • Header is 2 bytes: magic 0x0D at block +0, slot index at block +1.
  • Integrity is a complemented 16-bit word sum: stored u16le at block +0x388 equals ~sum16 of the 452 u16le words at block +0x000..+0x387. This matches all 12 copies in cap-01-future-1.sav and correctly fails on the blank cap-00-future-0.sav.
  • The writer, reader, default-initialiser, save-all orchestrator, and its sole traced entry caller form a complete chain (Section 3).

Static-only (CONFIRMED_STATIC / HYPOTHESIS):

  • A sub-structure at block +0x204 (inferred from FUN_0800c4a8 pointer-index arithmetic matching seven default values in the .sav; the pointer literal itself is an unresolved _DAT_* placeholder in decompiled.c).
  • Attribution of the defaults at block +0x088, +0x090, +0x0A0, +0x0A3, +0x0A5 among several candidate writes whose _DAT_* offsets Ghidra did not resolve.

Open / unknown:

  • Exact EWRAM/IWRAM base address of the in-RAM save struct (unresolved literal-pool pointers; block-relative offsets are proven because the block is copied verbatim).
  • Semantic names of gameplay fields. The only non-blank sample is a freshly default-initialised save: its three slots differ only in byte +1 and the checksum. There is no progressed-gameplay sample, so no field can be named from observed gameplay values.
  • Trigger semantics of the top caller FUN_08057078 (no callers in callgraph.json; jumptable-driven).

Why not HIGH: the geometry, header, and checksum are fully verified, but field semantics and the RAM base rest on unresolved _DAT_* literals and a single default-state sample.

Redundancy and selection rule:

  • Each slot holds 4 byte-identical copies of one 908-byte block. In the populated sample, all copies within a slot are byte-identical (verified by direct comparison), and the three slots differ only at byte +1 (slot index) and the checksum word that covers it.
  • Writer FUN_0800c5cc writes the same RAM block to all 4 copies sequentially (dst += 0x38C per iteration) and verifies each with FUN_08098990, recording success if any copy verifies.
  • Reader FUN_0800c654 tries copies in order 0, 1, 2, 3. The first copy passing all three checks wins: byte +0 == 0x0D, stored checksum equals recomputed ~sum16, and byte +1 < 3. There is no generation, sequence, or newest-copy comparison; identical copies make order irrelevant in practice.
  • If all 4 copies fail, the reader calls the default-initialiser FUN_0800c4a8 on the RAM block. The block is only persisted when the caller subsequently runs the writer.
  • No generation/sequence counter exists in the format. The only candidate byte, block +2, is a clamped 0..4 value overwritten by FUN_080563ac on every save (Section 3), not an incrementing counter.
  • The reader validates byte +1 < 3 but never compares it against the requested slot index. A block stamped with another slot's index is predicted to be accepted in this slot (fuzzing target in Section 6).

4. Magic Signatures & Checksum / Integrity Algorithm

Magic

  • One magic only: byte 0x0D at block offset 0. The writer stamps it (*(undefined1 *)_DAT_0800c650 = 0xd;) and the reader tests it ((char)*puVar1 == '\r'). It is not ASCII. There is no multi-byte signature and no SDK tag.
  • Verified in sav: 0x0D at every copy base of the populated file (0x0000, 0x038C, 0x0718, 0x0AA4, 0x0E30, …); 0xFF everywhere in the blank file.

Checksum formula

sum16   = ( Σ block_u16le[i]  for i in 0 .. 451 ) mod 65536     # bytes 0x000..0x387
stored  = (~sum16) & 0xFFFF                                     # u16le at byte 0x388
accept  = (stored == (~recomputed_sum16) & 0xFFFF) and block[0] == 0x0D and block[1] < 3
  • Algorithm class: sum16_le with ones'-complement storage (bitwise NOT of the wrapping 16-bit sum). No seed, no XOR key, no CRC, little-endian words.
  • Covered range: block bytes 0x000..0x387 inclusive (452 words). Stored at block bytes 0x388..0x389. Block bytes 0x38A..0x38B are copied but neither covered nor stored.
  • Decompiled proof (writer, FUN_0800c5cc in decompiled.c): the loop for (; psVar5 < psVar3; psVar5++) uVar2 += *psVar5; runs from the base to base + 0x1C4 words, then _DAT_0800c650[0x1C4] = ~uVar2;. The reader (FUN_0800c654) repeats the identical sum and compares *puVar6 == (ushort)~uVar3.

6. Save Fuzzing & Counterfactual Verification Plan

Checksum repair procedure for every mutation below that requires it: recompute sum16 over the mutated copy's bytes 0x000..0x387 as u16le words, write (~sum16) & 0xFFFF as u16le at that copy's +0x388, and apply the identical mutated copy to all 4 copies of the target slot unless the mutation says otherwise. Reload by resetting the emulator with the mutated .sav in place of cap-01-future-1.sav (no paired .ss states exist in this workspace — states/ is empty — so cold-reload is the test path; the PACKET cold-reload probe already shows save_preserved_on_load: true with a visual delta). Appendix: Method and Limitations

  • All geometry, checksum, and observed-value claims were computed directly from the two .sav binaries with Python in this workspace; the checksum output in Section 4 is the verbatim result.
  • All function claims were read from the bodies in decompiled.c and cross-checked against callgraph.json. The one graph gap (the three func_0x… driver edges) is disclosed in Section 3.
  • Hard limitations: _DAT_* literal-pool values are unresolved placeholders in the provided decompilation, so absolute RAM addresses and several default-write attributions cannot be proven from this corpus; every such claim above is rated CONFIRMED_STATIC, HYPOTHESIS, or UNKNOWN accordingly. No progressed-gameplay .sav exists in the corpus, so field semantics beyond defaults are unknowable from this packet alone.
