1. Executive Summary & Overall Confidence

Overall confidence: MEDIUM (physical format and integrity are HIGH; field semantics are LOW–MEDIUM).

Proven (verified against both .sav files, 6/6 slot instances):

  • Media is EEPROM 4 Kbit = 512 bytes, organised as 64 blocks of 8 bytes. File size, FUN_0800d368(0x1000) geometry call, and DMA bit lengths all agree.
  • Layout is one 8-byte global header + three independent 120-byte (0x78) profile slots + 144 bytes of 0xFF unused tail. There is no mirroring, no backup copy, and no per-slot generation counter.
  • Every 8-byte EEPROM block is stored in the .sav file byte-reversed relative to the in-RAM image (equivalently: serial u16 words are reversed and each u16 is MSB-first on the wire). This transform was not assumed — it is the transform that makes the checksum verify (Section 4).
  • Each slot carries a 32-bit magic/sentinel at RAM slot +0x00 and a CRC-16 (poly 0x1021, init 0x0000, MSB-first, no final XOR) over RAM slot bytes [0, 116), stored little-endian at RAM slot +116. Computed values match stored values on all 6 slots in both files (empty 0x91E9, occupied slot 0 in cap-01 0x2F6D).
  • Occupied magic is 0xC0DEB00B; the empty-slot sentinel is 0x3F214FF4. The header uses 0xC0DEB00B plus a boot counter byte that increments modulo 0x18 (24).

Proven statically (code-proven, semantics open):

  • The complete writer/reader architecture: DMA driver (0x080466e0), EEPROM read/write/verify (0x08046760/0x08046824/0x08046984/0x080469dc), load/flush (0x0800d32c/0x0800d2ac), serializer/deserializer (0x0802cec4/0x0802cffc), validator/reset (0x0802d154/0x0802d18c), header check/fix (0x0802d1c4/0x0802d1d8), and every caller chain in Section 3.
  • The structural field map (offsets, sizes, types, writers, readers, game-object source offsets) in Section 5.

Open / not proven:

  • Absolute RAM addresses. All _DAT_080xxxxx literal-pool contents are placeholders in decompiled.c; the save-manager struct base and the game-object base (returned by FUN_080177ec) cannot be read from this workspace. Logical RAM-image offsets are proven; absolutes are honestly null in save-format.json.
  • Gameplay names for fields at slot +0x04..+0x73. Structure is proven; what each array/bit means in gameplay terms is not derivable clean-room from these files.
  • Whether the load/flush loops iterate 64 blocks (full mirror incl. tail) or 46 (header+slots only); indistinguishable from the samples (Section 2).
  • The CRC table bytes in ROM (_DAT_0803b204) are not in the workspace; polynomial 0x1021 is proven by verification, not by reading the table.
  • No .ss states were supplied, so Section 6 is a plan, not results.

FUN_0800d368(param) is the size setter: it stores (int)param >> 6 into the EEPROM descriptor word and calls FUN_08046698((param & 0x3FFFFFF) >> 10). The only traced call passes 0x1000 (4096 bits): descriptor block-count becomes 64 and the type selector receives 4. FUN_08046698 branches on 4 vs 0x40 vs other to install a descriptor whose +4 word is the block count limit (checked as param_1 < *(ushort *)(desc + 4) in both block drivers) and whose +8 byte is the address-bit count (used for DMA lengths). The literal descriptor contents are not in this workspace, so "64 blocks / 6 address bits" is CONFIRMED_STATIC-by-arithmetic + file size, not read from ROM.

2.2 Geometry

The EEPROM is mirrored into RAM starting at manager + 0x0C (both load FUN_0800d32c(param + 0x0C) and flush FUN_0800d2ac(_DAT + 0x0C) use that base). The manager struct is set up by FUN_0801c094(struct, 3):

param_1[1] = (int)(param_1 + 3);   // byte +12: header pointer == RAM image base
param_1[2] = (int)(param_1 + 5);   // byte +20: slots array == RAM image base + 8
*param_1   = param_2;              // count = 3

Hence the RAM image (and therefore the EEPROM) layout is:

Slot stride 0x78 is proven twice: FUN_0801c094 validates slots at param_1[2] + i * 0x78, and FUN_0801c0f0(idx) returns slots_base + idx * 0x78.

Per-block byte reversal (critical for reading any field from the raw file): for each aligned 8-byte block, file_byte[i] = ram_byte[block_base + (7 - i)]. Equivalently the EEPROM serial stream carries u16 words MSB-first and in reverse word order (FUN_08046760 stores the first received u16 at buffer + 6 and decrements). A logical field's bytes therefore occupy the same 8-byte block range in the file, reversed within each block. All "file offsets" in Section 5 are the start of that reversed range for slot 0; add 0x78 per slot index for slots 1–2.

2.3 What the two samples actually contain

Reconstructed RAM image (transform above applied):

  • cap-00-future-0.sav: header valid (0xC0DEB00B, counter 0x10); all three slots empty (sentinel 0x3F214FF4, CRC 0x91E9, everything else zero); tail 0xFF.
  • cap-01-future-1.sav: header identical; slot 0 occupied (magic 0xC0DEB00B, CRC 0x2F6D, sparse progress fields — Section 5); slots 1–2 still empty; tail 0xFF.

The 20-byte diff between the files (packet §12 / hexdump_and_diffs.txt) is exactly slot 0 transitioning empty → occupied plus its CRC change at file 0x07A–0x07B. No other slot, the header, or the tail changed. That is direct byte-level evidence that slots are independent and that saving slot 0 does not touch slots 1–2.

2.4 Redundancy, counters, selection rule

  • No redundancy. There is exactly one copy of the header and one copy of each slot. No mirror, no A/B ping-pong, no duplicate block anywhere: the three slots are byte-identical only when all are empty, and slot 0 diverges alone in cap-01.
  • No per-slot generation/sequence counter. No field inside a slot is incremented on save by any traced writer; the serializer (FUN_0802cec4) copies game-object fields and recomputes only magic + CRC. A stale-but-CRC-valid slot cannot be distinguished from a fresh one by the format itself.
  • The only counter is global: header RAM +4, incremented as (old + 1) % 0x18 by FUN_0803b0dc on game init and flushed. It does not select slots (both samples hold 0x10 while slot state changed underneath it, proving it is not a slot version).
  • Selection rule: slots are addressed purely by explicit index (FUN_0801c0f0(idx), idx < 3 checked in FUN_080163dc as *(param + 0xC) < 3). Validity is per-slot magic+CRC (FUN_0802d154). "First valid slot" probing exists only in UI/continue logic (FUN_08030778 tests 0, 1, 2 in order). Empty sentinel slots are deliberately re-created by FUN_0802d18c during init (FUN_0801c094) so an erased/corrupt slot becomes a clean empty slot in RAM; the rewrite reaches EEPROM on the next flush — matching the packet probe observation (save_rewritten_after_mutation: true, no revert to blank boot).

3. Save Writer, Reader & Caller-Chain Architecture

All addresses are 0x08xxxxxx ROM addresses as named in ghidra/decompiled.c. "How mapped" for callers: a caller is listed only if (a) its decompiled body contains a direct call to the callee, and (b) ghidra/callgraph.json corroborates it where the graph records the edge (the graph drops some edges that Ghidra emitted as func_0x… calls in bodies — e.g. FUN_0801be94 → FUN_0801c094 — so body text is primary, graph is corroboration; discrepancies are noted).

3.1 Low-level hardware I/O driver

FUN_080466e0(src, dst, count) — DMA3 transfer engine (CONFIRMED_STATIC). Saves a control register (*_DAT_08046740 = 0 during transfer), programs three DMA registers from its arguments (*_DAT_08046750 = param_1, *_DAT_08046754 = param_2, *_DAT_08046758 = (param_3 & 0xFFFF) | 0x80000000), spins while the high halfword's 0x8000 busy bit is set, then restores the saved control. The register literal addresses are unresolved placeholders in the decompilation; identifying them as DMA3 SAD/DAD/CNT at 0x040000D4+ follows from the packet's hardware spec, the 0x80000000 enable bit, and the fact that every caller passes 0x0D000000 (EEPROM) as one endpoint. Callers: FUN_08046760, FUN_08046824 only (callgraph agrees).

FUN_08046760(block_index, out_8bytes) — EEPROM Read8 (CONFIRMED_STATIC). If block_index < descriptor_block_count: builds a bit array on the stack — start/opcode bits 1,1 then the block address MSB-first (addr_bits entries) — DMAs addr_bits + 3 halfword-bits to 0x0D000000, then DMAs 0x44 (68) halfwords back from 0x0D000000, and reassembles 4 u16s: each u16 = (acc << 1) | next_bit over 16 bits, stored to out + 6, +4, +2, +0 in that order. Returns 0 on success, descriptor default (uRam0804677c) if the index is out of range. This bit order is the sole source of the file block byte-reversal described in §2.2.

FUN_08046824(block_index, in_8bytes, wait_flag) — EEPROM Write8 (CONFIRMED_STATIC). Mirror image: expands the 4 input u16s plus the block address into a addr_bits + 64-bit stream with start bits 0,1, DMAs addr_bits + 0x43 bits to 0x0D000000, then polls the EEPROM data bit (uRam0d000000 & 1) against a timer (threshold 0x88 elapsed ticks; timeout path returns a non-zero code). This is a serial EEPROM bit-bang over DMA3, not SRAM byte-copy and not a Flash 0x5555/0x2AAA command sequence — no 0x0E000000 access exists in any traced save function.

FUN_08046810(block, buf) — wrapper calling FUN_08046824(block, buf, 1) (wait enabled). Caller: FUN_080469dc only.

FUN_08046984(block, expected_8bytes) — Verify8 (CONFIRMED_STATIC). Re-reads the block via FUN_08046760 into a stack buffer and compares 4 s16s; returns 0x8000 on first mismatch, 0 if all match. Caller: FUN_080469dc only.

FUN_080469dc(block, buf) — Write8-with-verify, 3 retries (CONFIRMED_STATIC). Loops at most 3 times: FUN_08046810 then, if that returned 0, FUN_08046984; breaks on verified success. Caller: FUN_0800d2ac only (callgraph agrees; note save_related_functions.c lists no caller for it because its seed extraction stopped at 2 hops — the body-level caller in decompiled.c:1196-1200 region of FUN_0800d2ac is explicit).

FUN_08046698(size_code) / FUN_0800d368(bits) — EEPROM geometry select (CONFIRMED_STATIC). See §2.1. FUN_0800d368 is called only from FUN_0801c094 with 0x1000.

There is no erase function: EEPROM bytes are overwritten block-wise; "erase" of a slot is the RAM-side memset in FUN_0802d18c followed by a normal flush.

3.2 Block-layer load / flush

FUN_0800d32c(ram_image) — Load (CONFIRMED_STATIC). for (i = 0; i < count; i++) FUN_08046760(i, ram_image + i*8), stopping early on non-zero return; returns true iff the last read returned 0. count is the descriptor word (*_DAT_0800d364), inferred 64 (§2.1; a 46-block count is indistinguishable from the samples). Sole caller: FUN_0801bfb4(param + 0x0C).

FUN_0800d2ac(ram_image) — Flush/save (CONFIRMED_STATIC). For each block i: read the live EEPROM block into a stack buffer via FUN_08046760; compare its 4 s16s against ram_image + i*8; only on mismatch call FUN_080469dc(i, ram_image + i*8) (write+verify). Accumulates errors; returns true iff none. This read-compare-write-skip is why the cap-00 → cap-01 file diff is only 20 bytes and why the mutated-byte probe caused a rewrite of just the affected content. Sole caller: FUN_0801be94.

FUN_0801bfb4(manager) — Load wrapper; FUN_0801be94() — Flush wrapper (CONFIRMED_STATIC). Both bracket the block call with the same guard sequence (FUN_08034660 check + FUN_08034654/FUN_08034360/FUN_080345a8 suspend path, FUN_080019fc, FUN_08001ba0, FUN_08001e40 before; FUN_08001e24, FUN_08001b84, FUN_080019d8 after). Those guards are assumed IRQ/sound suspend-resume from context — HYPOTHESIS as to purpose, proven only as bracketing. FUN_0801be94 additionally lazily inits the manager (if (*flag == 0) { FUN_0801c094(_DAT_0801bf30, 3); *flag = 1; }, using its own static manager pointer) before FUN_0800d2ac(manager + 0x0C). Callgraph lists both wrappers' callees incompletely (body text shows the FUN_0801c094 call that the graph omits).

3.3 Manager, header, validation

FUN_0801c094(manager, 3) — Save-manager init (CONFIRMED_STATIC). Sets count/pointers (§2.2), FUN_0800d368(0x1000), loads via FUN_0801bfb4, then: if FUN_0802d1c4(header) reports magic mismatch → FUN_0802d1d8(header) rewrites header magic in RAM; then for each of 3 slots, if FUN_0802d180(slot) reports invalid → FUN_0802d18c(slot) resets it to a clean empty slot in RAM. Callers (body-verified): FUN_0801be94, FUN_0801c0f0, FUN_0801c120 (each behind a first-use flag). This init-mutates-RAM behaviour means merely booting the game repairs header/slot structure in RAM; EEPROM is only rewritten on the next flush.

FUN_0801c0f0(idx) / FUN_0801c120() — Accessors (CONFIRMED_STATIC). Return slots_base + idx * 0x78 and the header pointer respectively, after lazy init. These are the only sanctioned ways callers obtain slot/header RAM pointers, which is how every field access below was attributed to a slot.

FUN_0802d1c4(header) / FUN_0802d1d8(header) — Header magic check/fix (CONFIRMED_STATIC). Check computes (-(*hdr ^ K) | *hdr ^ K) >> 0x1F — 1 iff *hdr != K; fix stores K at header + 0 (4 bytes only; counter and FF bytes untouched). K is a ROM literal; from the reconstructed header in both files K = 0xC0DEB00B (CONFIRMED_VERIFIED as a value, since the header passes this check in both samples and the same constant appears as occupied slot magic).

FUN_0802d1bc(header, v) / FUN_0802d1c0(header) — Header byte +4 set/get (CONFIRMED_STATIC). Single-byte accessors for the counter byte. Sole traced user: FUN_0803b0dc.

FUN_0802d140(slot) — Slot CRC compute (CONFIRMED_VERIFIED, Section 4). Returns FUN_0803b138(0, slot, 0x74).

FUN_0802d154(slot) / FUN_0802d180(slot) — Occupied-slot validation (CONFIRMED_STATIC). FUN_0802d154 returns 1 iff *slot == occupied_magic && (short)slot[0x1D] == FUN_0802d140(slot) (i.e. magic at RAM +0, stored CRC at RAM +116). FUN_0802d180 returns FUN_0802d154(...) ^ 1 — so it returns 0 for a valid occupied slot, 1 otherwise (including clean empty slots). Every caller below was mapped through this inverted convention; misreading it inverts load-vs-create logic.

FUN_0802d18c(slot) — Reset slot to empty (CONFIRMED_STATIC + sentinel value VERIFIED). Memset via SWI wrapper FUN_08046a28(&zero, slot, ctrl) (GBA CpuSet, length control literal unresolved — extent 0x78 inferred from stride and from the empty slots being fully zero outside magic/CRC), then *slot = empty_sentinel, then stores FUN_0802d140(slot) at RAM +116. The sentinel value 0x3F214FF4 is CONFIRMED_VERIFIED: all five empty slots in the samples have exactly this word plus the CRC that this procedure would compute over it (§4).

3.4 Serialization / deserialization

FUN_0802cec4(slot, gameobj) — Serialize (CONFIRMED_STATIC). Writes, in RAM slot offsets (game-object source offsets in brackets; gameobj is the FUN_080177ec() singleton):

  • +0x04 u8 ← FUN_080170f8 [obj +0x48 if obj +0xA0==0 else +0x58], +0x05 u8 ← FUN_080170d0 [obj +0x50/+0x60], +0x06 u8 ← FUN_080170bc [obj +0x54/+0x64] — only if FUN_080170e4(gameobj) == 0 (obj +0x4C/+0x5C); otherwise these three bytes are left as-is (stale-byte quirk, noted for fuzzing).
  • +0x08 u16 ← (short)*(obj + 0x6C).
  • +0x0A u16[6] ← FUN_080176d0 [obj +0x0C + i*2], +0x16 u16[6] ← FUN_080176c4 [obj +0x18], +0x22 u16[6] ← FUN_080176b8 [obj +0x24], i = 0..5.
  • +0x2E u16 ← FUN_080174a4 [obj +0x30] (same conditional block as above).
  • +0x07 u8 ← FUN_08017060 [obj +0x58, truncated], +0x30 u16 ← FUN_08017160 [obj +0x32], +0x32 u16 ← FUN_08017140 [obj +0x34], +0x34 u16 ← (short)*(obj + 0x98), +0x36 u16 ← (short)*(obj + 0x94), +0x38 u16 ← FUN_08017114 [obj +0x9C].
  • +0x3C bytes[56] ← FUN_08008204(FUN_08017760(gameobj) = obj + 0xA8, slot + 0x3C, 0x0E): two 7-u32 bitset copies (halves from obj +0xA8 and obj +0xB0 sub-objects via FUN_08003418).
  • Finally *slot = occupied_magic and *(u16*)(slot + 116) = FUN_0802d140(slot).

Sole caller: FUN_080163dc. Callgraph records no callers for FUN_0802cec4 (graph gap); the body call site at FUN_080163dc is explicit in decompiled.c.

FUN_0802cffc(slot, gameobj) — Deserialize (CONFIRMED_STATIC). Exact mirror via the paired setters (FUN_08017068/64/80/6C/94, FUN_080176AC/A0/94, FUN_080174A0, FUN_0801715C/3C, FUN_080174C8/C0, FUN_0801710C, FUN_08008228 for the +0x3C blob into obj +0xA8). It performs no magic/CRC check itself; every caller gates with FUN_0802d180 first. Callers (body-verified): FUN_08016a80, FUN_0802c970.

FUN_0803b138(seed, bytes, len) — Generic CRC-16 (CONFIRMED_VERIFIED). MSB-first table loop crc = (crc << 8) ^ table[((crc >> 8) ^ byte)], unrolled by 4 with a remainder head; table at _DAT_0803b204 (ROM, not in workspace). Only caller in the save system: FUN_0802d140. Polynomial identification is by verification (§4), not by reading the table.

3.5 Every traced caller chain (how each mutates the RAM struct before flush)

  1. Save game — FUN_08016a80 → FUN_080163dc → FUN_0802cec4 → FUN_0801be94 → FUN_0800d2ac → FUN_080469dc → FUN_08046810/FUN_08046824 → FUN_080466e0.

FUN_080163dc(caller_ctx): if *(caller_ctx + 0xC) < 3 (slot index), slot = FUN_0801c0f0(index) (Ghidra drops the argument in its rendering; the index source is the caller's +0xC field set by FUN_08016a80), FUN_0802cec4(slot, FUN_080177ec()) overwrites the RAM slot in place (fields as §3.4, magic+CRC last), then FUN_0801be94() flushes the whole RAM image with block-level write-skip. This is the only chain that creates occupied slots.

  1. Load-or-create slot — FUN_08016a80(ctx, slot_index).

Stores slot_index at ctx + 0xC; if FUN_0802d180(slot) == 0 (valid occupied): FUN_0802cffc(slot, gameobj) loads it into the game object and restores two global fields from obj +0x98/+0x94. Else: falls into FUN_080163dc(ctx) (chain 1) to create/save. Mapped by reading FUN_0802d180's inverted return (§3.3) against the branch in FUN_08016a80.

  1. Boot/init repair — FUN_0803baf8 → FUN_0803b0dc → FUN_0801c120/FUN_0802d1c0/FUN_0802d1bc → FUN_0801be94.

FUN_0803baf8 (game init) calls FUN_0803b0dc once (manager flag clear). FUN_0803b0dc ensures init via FUN_0801c120, does FUN_0802d1bc(header, FUN_0800026a(FUN_0802d1c0(header) + 1, 0x18)) — header counter = (old + 1) % 24 (FUN_0800026a is the BIOS divide-remainder wrapper: it returns extraout_r1 from FUN_08000254) — then flushes. RAM mutation before flush: exactly one header byte.

  1. Init/validate — FUN_0801c094 (chain in §3.3). RAM mutations before any later flush: header magic repair + empty-reset of invalid slots. Reached lazily from FUN_0801be94, FUN_0801c0f0, FUN_0801c120.
  2. Slot-select UI (read-only) — FUN_0802c970 → FUN_0801c0f0 → FUN_08047344 (memcpy 0x78) → FUN_0802d180 → FUN_0802cffc.

Copies each slot to a stack buffer (auStack_168[120]), and only for valid occupied slots deserializes into a temporary object to format display strings using counters FUN_08016c80, FUN_08017224, FUN_0801758c (bit-count over array B), FUN_080174d0 (bit-count over array C). No EEPROM or RAM-image mutation.

  1. Continue probe (read-only) — FUN_08030778 → FUN_0801c0f0(0,1,2) → FUN_0802d180.

Returns through FUN_0802c970 construction; probes slots in order and, if none is valid, triggers a fallback via FUN_0801ca78. No mutation.

No other callers of the serializer, deserializer, validator, reset, load, or flush functions exist in decompiled.c (verified by exhaustive grep for each address, §"Method" note) — the chains above are complete within this workspace. Functions FUN_0800d474 etc. near the EEPROM wrappers in address order are game-object constructors that merely share the 0x0800dxxx neighbourhood and the FUN_08046a28 SWI memset; they never touch FUN_08046760/FUN_080469dc and are not save code.

4.2 Checksum algorithm (exact)

// FUN_0802d140(slot)  — decompiled.c
undefined2 FUN_0802d140(undefined4 param_1) {
  return func_0x0803b138(0, param_1, 0x74);        // seed 0, length 116
}
// FUN_0803b138(seed, byte *p, int len) — core loop (remainder head + 4× unroll)
crc = seed & 0xFFFF;
for each byte b:  crc = ((crc << 8) ^ table[((crc >> 8) ^ b)]) & 0xFFFF;
return crc;
  • Algorithm: MSB-first table-driven CRC-16, polynomial 0x1021, init 0x0000, no input/output reflection, no final XOR — the CRC-16/XMODEM parameter set (name is descriptive only; identification is by the verification below, since the table itself is not in the workspace).
  • Covered range: RAM slot bytes [0x00, 0x74) — 116 bytes, including the magic, excluding the stored CRC and the 2 padding bytes.
  • Stored: u16 little-endian at RAM slot +116 (param_1[0x1D] in FUN_0802d154; *(undefined2 *)(param_1 + 0x1D) in FUN_0802d18c/FUN_0802cec4). In the file (slot 0) at 0x07A–0x07B as bytes 91 E9 (empty) — i.e. the file holds the value big-endian-looking purely because of the per-block byte reversal.
  • Checked in FUN_0802d154 together with the magic; recomputed on every serialize (FUN_0802cec4) and every empty-reset (FUN_0802d18c).
  • The header has no checksum — magic equality only (FUN_0802d1c4). The tail has no integrity at all.

4.3 Python verification against the real .sav files (executed in this workspace)

Method: read each .sav, byte-reverse each 8-byte block to reconstruct the RAM image, slice slots at RAM-image 8 + i*120, compute the CRC above over slot[0:116], compare to u16 LE at slot[116:118]. import struct
def ram_image(path):
    d = open(path, 'rb').read()
    return b''.join(d[i:i+8][::-1] for i in range(0, len(d), 8))
def crc16(data, poly=0x1021):
    crc = 0
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ poly) & 0xFFFF if crc & 0x8000 else (crc << 1) & 0xFFFF
    return crc
for fn in ('cap-00-future-0.sav', 'cap-01-future-1.sav'):
    ram = ram_image('saves/' + fn)
    for s in range(3):
        slot = ram[8 + s*120 : 8 + (s+1)*120]
        print(fn, s, hex(struct.unpack('<I', slot[0:4])[0]),
              hex(crc16(slot[:116])), hex(struct.unpack('<H', slot[116:118])[0]))

Checksum-repair procedure for any hand-edited slot (used by Section 6): apply edits in RAM-image space, recompute as above, store LE at RAM +116, then byte-reverse each 8-byte block back to file space. Editing raw file bytes without this transform will corrupt the slot.

The packet's mutation probe is consistent in detail: probe offset 0x0C is slot 0's file magic; integrity_check_confirmed: true = FUN_0802d154 failing; save_rewritten_after_mutation: true = FUN_0801c094 empty-reset + FUN_0800d2ac write-skip flush; reverted_to_blank_on_mutation: false = the reset produces the sentinel empty slot, not a zeroed file.
