GBA Save Format — Clean-Room Reverse-Engineering Report

Title: Arthur and the Invisibles (USA) (En,Fr,Es) · Release key: B2NE-r0-c17e876e6caf7300 · Game code: B2NE / family B2N

ROM SHA-256: c17e876e6caf7300b12607265ebd6f3ec4babc507dceae2e7c606cf732bfd9bb · Community: comm-003

Corpus used (nothing else): saves/cap-00-future-0.sav, saves/cap-01-future-1.sav (512 B each), saves/hexdump_and_diffs.txt, ghidra/decompiled.c (291 functions), ghidra/save_related_functions.c (5 functions), ghidra/callgraph.json. All address literals of the form _DAT_xxxxxxxx in the decompilation are unresolved literal-pool indirections, so absolute EWRAM addresses of the save struct cannot be recovered from this corpus; struct-relative offsets (G+n, S+n) are exact. No third-party game-specific source was used.

1. Executive Summary & Overall Confidence

Overall confidence: MEDIUM (core format HIGH, gameplay semantics incomplete).

Proven by decompiled code and .sav bytes jointly (CONFIRMED_VERIFIED):

  • Media is EEPROM, 512 bytes (EEPROM_V124, SDK tag in PACKET §1), accessed as 64 words × 8 bytes through DMA3 to 0x0D000000.
  • Layout is one 8-byte global header + three independent 128-byte profile slots at EEPROM byte offsets 0x08 / 0x88 / 0x108, ending at 0x188; bytes 0x188–0x1FF are never written (erased 0xFF).
  • Every 8-byte EEPROM word appears in the .sav file byte-reversed relative to the game's RAM buffer (proven in §4: only the reversed frame satisfies both the checksum-at-+0 checks and the +7 == 0x03 / +2 == 0x01 marker checks simultaneously).
  • Integrity is an 8-bit additive checksum stored as ones' complement: CK = ~(sum of covered bytes) & 0xFF, i.e. sum(covered)+CK == 0xFF. Two instances exist (global header, per-slot). Verified numerically on both captures for all four checksummed regions (script output in §4). CRC-16 hypotheses do not match.
  • Boot/load chain FUN_080006f4 → FUN_080007bc (global validate-or-rebuild) + FUN_08000240(slot) ×3 (slot validate-or-rebuild) is fully traced, including init defaults that match the .sav bytes byte-for-byte.

Still open (HYPOTHESIS/UNKNOWN, see §5–§6):

  • No gameplay progress flush (RAM slot → EEPROM outside the init/repair path) and no gameplay writers of slot record bytes exist in the 291-function trace corpus; only the boot/load/repair writers were traced.
  • Slot record area (S+0x0C, 21×4 B) is all-zero in both captures (empty saves), so per-record semantics are unknown.
  • Global fields G+3=0x20, G+4=0x30 semantics unknown (consumed by FUN_080009c8 chain); G+2 is a flag set to constant 1 by FUN_08000874, not a proven incrementing counter.
  • Absolute RAM mirror addresses unknown (unresolved _DAT_ literals).

Cold-reload probe in PACKET §1 (probe_offset_hex 0x5, mutated byte reverted, save rewritten) is consistent with §4: file offset 0x05 is global field G+2; mutating it without repairing the checksum at file 0x07 invalidates the header, forcing rebuild.

2. Physical Media, Slot Geometry & Redundancy

  • Total size: 512 bytes (EEPROM 4K = 4 Kbit). SDK tag EEPROM_V124@14346280. Both captures are 512 B, SHA-256 407dde00bb2de2bc… / 1f90b1a1228921ec….
  • Device geometry: 64 EEPROM words × 8 bytes. Proven by FUN_0828b228 (word_addr = byte_offset >> 3), by the 8-byte stepping loops in FUN_0828b180/FUN_0828b1b8, and by 4×u16 (64-bit) transfers in FUN_0829a644/FUN_0829a708.
  • Address-bit count / word count are read from a device-descriptor struct (*(u16*)(desc+4), *(u8*)(desc+8)) in FUN_0829a644/FUN_0829a708; literal values are not in the corpus (CONFIRMED_STATIC for mechanism, values inferred as 64 words from the 512 B image).
  • Layout (file offsets):

  • Number of slots/copies: 3 profile slots. They are independent profiles, not mirrors/backups: all three are byte-identical in both captures only because all three are freshly initialized empty profiles. There is no primary/backup pair, no cross-slot copy, and no fallback-slot selection on corruption — a corrupt slot is re-initialized in place (FUN_08000240, §3).
  • Generation/sequence counters: none found. No per-slot generation field exists; the only changing byte between captures is global G+2 (0→1), written as constant 1 by FUN_08000874, so it is classified as a flag, not a sequence counter (HYPOTHESIS).
  • Selection rule: FUN_080006f4 always loads/repairs global header, then slots 0, 1, 2 in order. Current-slot index is global byte G+6 (observed 0x00; used by FUN_0800083c to index slot*0x80 + base + 0x0C). No newest-of-copies comparison exists.
  • Fill bytes: written area background 0x00; unwritten tail 0xFF (EEPROM erased state). Dominant fill 0x00 per PACKET §1 matches.

  • FUN_080007bc() — LoadGlobalHeader: begin-read; FUN_0828b180(buf,8); if read ok and buf[0]==~sum(buf[1..7]) and buf[7]==0x03, accept (return 1). Else end-access, FUN_08000388() (init defaults in RAM), FUN_08000770() (persist), return 0. Caller: FUN_080006f4†.
  • FUN_08000388() — InitGlobalHeader (RAM only): zero-fill 8 B via FUN_0829a548 (BIOS SWI 0x0B copy/fill), then G+1=0, G+2=0, G+3=0x20, G+4=0x30, G+5=1, G+6=0, G+7=0x03. Caller: FUN_080007bc.
  • FUN_08000770() — SaveGlobalHeader: CK=~sum(G+0..G+6) stored at G-1 frame (i.e. RAM checksum byte G+0 in reader frame), begin-write, FUN_0828b1b8(buf,8), end. Caller: FUN_080007bc only (in corpus).
  • FUN_08000240(slot) — LoadOrRepairSlot: begin-read; FUN_0828b228(slot*0x80+8); FUN_0828b180(slotRAM,0x80); if read ok and S+0==~sum(S+1..S+127) and S+2==0x01, accept. Else end, FUN_0800030c(slot) init, recompute CK=~sum(127 bytes), begin-write, FUN_0828b228(slot*0x80+8) + FUN_0828b1b8(slotRAM,0x80), end. Caller: FUN_080006f4 (loop slot=0..2).
  • FUN_0800030c(slot) — InitSlot (RAM only): zero-fill via FUN_0829a548; u32@S+4=0; S+1=0xFF; u32@S+8=1; S+2=0x01 (valid); then 21 iterations stride 4 masking record bytes rec+0 &= 0xF0, rec+1 &= 0x80 from S+0x0C. Caller: FUN_08000240†.

4. Magic Signatures & Checksum / Integrity Algorithm

4.1 Magic signatures

There are no ASCII magics (matches PACKET §1 ascii_magic_strings: []). Two 1-byte structural markers exist:

4.2 Checksum formula (exact)

  • Algorithm: 8-bit additive sum, stored as ones' complement (~sum & 0xFF). No CRC, no XOR-fold, no seed. Byte order irrelevant (addition commutative). Stored size 1 byte.
  • Global: CK(G+0) = ~(G+1+…+G+7) & 0xFF, file offset 0x07, covering file 0x00–0x06. Invariant: sum(file 0..7) == 0xFF.
  • Proof: FUN_08000770 sums 7 bytes and stores ~bVar1 before an 8-byte FUN_0828b1b8 write; FUN_080007bc recomputes ~sum(bytes 1..7) and compares to byte 0 in RAM frame.
  • Per-slot: CK(S+0) = ~(S+1+…+S+127) & 0xFF, file offsets 0x0F / 0x8F / 0x10F, covering the slot's remaining 127 RAM bytes.
  • Proof: FUN_08000240 sums 0x7F bytes from S+1, compares ~sum to S+0 and S+2==1; on failure re-inits, recomputes over 127 bytes, stores ~sum, writes 0x80 bytes.
  • Word byte-reversal: file byte k of each 8-byte word = RAM byte 7-k of that word. Proven because, in the straight file frame, the slot check would need marker S+2==0x00 (contradicting code), while in the reversed frame stored FE, marker 01, init FF/u32=1, and global marker 03 all match simultaneously.

6. Save Fuzzing & Counterfactual Verification Plan

No paired .ss states ship in this corpus (states/ is empty), so each test is: edit .sav, cold-boot, observe title/menu + RAM (global/slot struct after FUN_080006f4), and diff the rewritten .sav. Checksum repair means restoring the sum==0xFF invariant (global: adjust file 0x07; slots: recompute ~(sum of reversed-frame S+1..S+127) into file slot_base+7).

Open questions

  • Gameplay progress flush (RAM slot → EEPROM outside init/repair) and record writers at S+0x0C are absent from the trace corpus; a progressed save or fuller trace is required.
  • Exact semantics of G+1 (selection), G+3=0x20, G+4=0x30, G+5=1, S+1=0xFF, u32@S+8=1, and whether G+2 is flag vs counter.
  • Who flushes the global header after FUN_08000874 mutates RAM (FUN_08000770 is only called from FUN_080007bc in corpus), and who calls FUN_080006f4.
  • Absolute EWRAM addresses of G/S structs (unresolved _DAT_ literals) and EEPROM descriptor literals (word count / address bits).
