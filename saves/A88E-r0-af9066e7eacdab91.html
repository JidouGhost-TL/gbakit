3. Save Writer, Reader & Caller-Chain Architecture

Hardware I/O Driver Functions

AddressRoleCallersDescription & Implementation Notes
0x081da72cwrite0x081da7ac, 0x081da870Shared DMA3 serial bitstream pump to/from the EEPROM bus window 0x0D000000. Disables an IRQ-related flag, programs DMA source/dest/count-control MMIO fields, sets the DMA-enable bit (0x80000000) on the count/control word, busy-waits on a 0x8000 status bit, restores the flag. Used by both the write and read routines below as the raw bit-transfer primitive. Not itself a read or write decision point, hence no single 'read'/'write' role label fits cleanly; classified as the common low-level transport.
0x081da7acwrite0x081da9d0[MMIO-SEED] EEPROM write: bounds-checks address against (ushort)(cfg+4), serializes a '11' write-opcode header + N address bits (N = (byte)(cfg+8), a configurable address width consistent with 4Kbit/64Kbit dual-geometry EEPROM drivers) + 64 data bits read from the caller's 8-byte buffer, then pumps header+address and then the 64 data bits via two calls to FUN_081da72c (second call uses fixed count 0x44 = 68, i.e. 64 data bits + framing).
0x081da870readnone[MMIO-SEED] EEPROM read: bounds-checks address, serializes a read-request bitstream (address bits framed with leading/trailing marker bits), pumps it via FUN_081da72c with count = address_bits + 0x43 (67), then polls the EEPROM-ready bit (uRam0d000000 & 1) in a timing/backoff loop (accumulator uStack_18 vs threshold 0x88, wraparound constant 0xe4) before returning a status code through an unresolved tail jumptable. callgraph.json reports callers: [] for this address, but source inspection of ghidra/decompiled.c shows FUN_081da85c calling it directly - a gap in the provided callgraph, documented for honesty.
0x081da85creadnoneThin wrapper: func_0x081da870(param_1, param_2, 1). Fixes the read routine's third argument to 1. Present only as source text in ghidra/decompiled.c; callgraph.json lists this address with empty callers and callees, which does not match the decompiled source and is flagged as a static-analysis gap rather than evidence of no relationship.
0x081da9d0checksumnoneNot a checksum/CRC - a literal write-then-read-back verification: reads back 4 halfwords via the FUN_081da7ac path and compares them against an expected caller-supplied 4-halfword buffer, returning 0x8000 on first mismatch or 0 if all 4 match. Labeled 'checksum' only because the JSON schema's closed enum has no 'verify' role; the correct characterization is 'bitwise write verification', not a derived/computed checksum.
